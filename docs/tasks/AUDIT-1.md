## Phase 2 chat (Phase 4)
### A1. [high] Reveal override fires on everyday UI questions and sends the raw capture with no confirmation
- **Where:** `Sources/Glance/Privacy/Redactor.swift:91`
- **Evidence:** revealRegex includes `\b(?:show|read|look at|see|use|include|tell me)\b.{0,40}\b(?:redacted|hidden|censored|masked|blacked[- ]out)\b`, `\bunhide\b` and `(?:stop|without)\s+(?:hide|hiding…)`. I tested the regex in Python on ordinary questions and all of these matched: "How do I show hidden files in Finder?", "Can I see hidden columns in this sheet?", "How do I unhide this row?", "Tell me why this layer is hidden", "How do I stop hiding the Dock?", "How do I include hidden folders in the search?". In Panel.swift:231, `let reveal = revealed || Redactor.userAskedToReveal(question)` passes this straight to send(), which then uses `packet.raw` and skips redacting every user turn.
- **Failure:** The user selects a spreadsheet or Finder window that shows a card number, IBAN or API key and asks "how do I show hidden columns?". The unredacted JPEG and OCR text go to the cloud provider. The '⚠️ Not redacted' preview is added to the thread at the same moment the request starts, so it is only a notice after the fact. Reveal then stays on for every follow-up until the next selection. A voice question that is mis-transcribed can trigger it the same way.
- **Fix:** Narrow the regex to explicit commands about Glance's own redaction (e.g. "don't redact", "unredact", "show the redacted …"), and drop bare `hidden`/`masked`/`unhide`/`stop hiding`. Better: require one tap to confirm before a revealed send. That gate is already planned in docs/tasks/PHASE4.md item 1.

### A2. [medium] Changing the provider mid-conversation sends the screen packet to the new provider with no new preview
- **Where:** `Sources/Glance/UI/Panel.swift:232`
- **Evidence:** `let announce = history.isEmpty || (reveal && !revealed)`. The provider is looked up again on every ask (`provider = try Providers.current()`), and send() attaches the packet to the first user turn on every request. The Settings picker writes `provider` to UserDefaults right away (Settings.swift:54-55), and the 'supportsImages' toggle is also read again on each ask.
- **Failure:** The user asks with the Local (Ollama) or DeepSeek text-only provider. The preview says 'Sending to Local…' or 'image stays on this Mac'. The user then switches to OpenAI or Claude in Settings, or turns on images, and clicks 'Explain more'. The selection image and OCR text (raw, if reveal is on) go to a different cloud provider, and no preview names it or says the image is now included. The assistant turns in history are also sent unredacted.
- **Fix:** Keep the provider id and supportsImages value from the first preview on the conversation. Set announce when either differs (or reset the conversation).

### A3. [medium] An answer cancelled by a new selection still runs: it carries the reveal flag and old history into the new selection and suppresses that selection's preview
- **Where:** `Sources/Glance/UI/Panel.swift:230`
- **Evidence:** In ask(): `let packet = await capture?.value` is not followed by any `Task.isCancelled` check. After it come `revealed = reveal`, `ContextPacket.send(...)` and `history += [...]`. pointed(at:) calls stop() (which only does `answering?.cancel()`) and then resets `history = []` and `revealed = false`. Once the cancelled task resumes it writes to the new conversation's state. AsyncThrowingStream ends with nil (no error) when its consumer is cancelled, so the `history +=` line runs.
- **Failure:** The user points at region A and asks Q1 while OCR is still running ('Reading your selection…'), then re-points at region B. The old task resumes: it sets `revealed = true` if Q1 had a reveal phrase, adds A's preview to B's thread, and appends [Q1, ""] to the new history. On the user's first question about B, `history.isEmpty` is false, so announce is false. B's packet is attached to Q1 and sent with no preview, and unredacted if Q1 turned reveal on. This breaks both rules that reveal resets on a new selection and that the preview comes first. Anthropic also gets an empty assistant turn.
- **Fix:** Add `guard !Task.isCancelled else { return }` right after `await capture?.value`. Also check that `capture` still identifies the same task before changing `revealed` or `history`.

### A5. [high] A card number is not redacted when more digits follow it on the same OCR line (expiry or CVC)
- **Where:** `/Users/bhargavagumpula/Projects/glance/Sources/Glance/Privacy/Redactor.swift:33`
- **Evidence:** `(?<!\d)(?:\d[ -]?){12,18}\d(?!\d)` is greedy and keeps taking the digits that follow the card, up to 19. isMatch then runs Luhn on that over-long string, fails, and nothing retries a shorter match. Verified outputs: "4242 4242 4242 4242 12/29 123" was unchanged (hits 0), "4111 1111 1111 1111 123" was unchanged, and "4111-1111-1111-1111 123" was unchanged. The PHONE rule also rejects the run (16 digits is more than 15).
- **Failure:** Stripe-style single-row card fields such as "4242 4242 4242 4242  12 / 29  123" OCR as one line. The full card number goes to the provider in the text and stays visible in the image.
- **Fix:** Make the repetition lazy, `(?:\d[ -]?){12,18}?\d(?!\d)`, so the match stops at the first digit run that is followed by a non-digit. Or retry Luhn on 13–19-digit prefixes when the full match fails. Add "4242 4242 4242 4242 12/29 123" to the self-test.

### A8. [medium] Env/config-style secrets are missed: the \b before the label fails after an underscore
- **Where:** `/Users/bhargavagumpula/Projects/glance/Sources/Glance/Privacy/Redactor.swift:22`
- **Evidence:** `(?i)\b(?:password|...|secret|api[ _-]?key|...)\b\s*[:=]`: in OPENAI_API_KEY or AWS_SECRET_ACCESS_KEY the label is preceded and followed by `_`, a word character, so the \b checks fail. Verified with 0 hits: "OPENAI_API_KEY=abc123def456ghi789jkl012mno", "AWS_SECRET_ACCESS_KEY=wJalrXUtnFEMI/K7MDENG/bPxRfiCYEXAMPLEKEY", "secret_key = abcdefghijklmnop1234", "STRIPE_SECRET_KEY=whsec_...", "api key abcd1234efgh5678ijkl9012". Only keys with a known prefix (sk-, AKIA, ghp_, ...) are caught.
- **Failure:** The user points Glance at a .env file or terminal output. AWS secret keys, webhook secrets and other unprefixed keys are sent unredacted.

### A10. [medium] PEM private key body lines are not redacted on the OCR path: redaction runs one line at a time

### A11. [medium] A saved key is sent to whatever host the Address field points at, including the default host after 'Reset to defaults'
- **Where:** `Sources/Glance/UI/Settings.swift:89`
- **Evidence:** Keys are stored per provider id, not per host. In Providers.current (AI/AIProvider.swift:71), `let key = Keychain.get(id)` is paired with `Config.baseURL(for: id)`, which is whatever is in UserDefaults. resetDefaults() runs `removeObject(forKey: key + providerID)` for model., baseURL. and supportsImages. but leaves the Keychain key in place. AnthropicProvider sets `x-api-key` and OpenAICompatProvider sets `Authorization: Bearer` for any host, and nothing checks the host. HANDOFF records the owner's current setup as: "DeepSeek key saved in Settings (Azure endpoint, model DeepSeek-V4.1-Flash, images off)".
- **Failure:** The owner's 'deepseek' provider holds the Azure AI Foundry key. If the owner clicks 'Reset to defaults' on that provider (or edits its Address), the next question goes to https://api.deepseek.com/chat/completions with `Authorization: Bearer <Azure key>`, so the Azure credential reaches a different company. The same happens with the Claude preset: changing its Address to any other host (for example, pasting the Azure endpoint while the picker still shows Claude) sends the Anthropic key in x-api-key to that host. If it changed and no new key was typed, call `Keychain.set(providerID, "")` and set saved = "Address changed: re-enter the API key." ### A12. [medium] No validation on the Address field: a key pasted there is stored in plain text in UserDefaults
- **Where:** `Sources/Glance/UI/Settings.swift:62`
- **Evidence:** `d.set(Config.normalizedBaseURL(baseURL), forKey: "baseURL.\(providerID)")`. normalizedBaseURL keeps the first line and trims endpoint suffixes, but it never checks for an http(s) scheme or a host. The only protection is the label `TextField("Address (not the key)", ...)`. The Model and Voice ID fields are plain TextFields, also saved straight to UserDefaults (`model.<id>`, `elevenLabsVoiceID`) with no check. The selftest only covers the endpoint-then-key multi-line paste ("…/chat/completions\nsecret\n").
- **Failure:** The owner pastes an Azure key into Address (this has already happened) and clicks Save. The key is written unencrypted to ~/Library/Preferences/ie.dublinhacx.glance.plist, which is readable by any process running as the user and is included in backups. The settings still say "Saved." On the next request, `URL(string: key + "/chat/completions")` builds a relative URL with no scheme, and the user sees only a generic 'unsupported URL' error with no hint that the key is in the wrong field. A key pasted into Voice ID is also sent in the URL path. The key stays in the plist until the owner overwrites that field. It is worth checking whether the earlier paste is still there.

Otherwise leave the old value and set saved = "Address must start with https:// — keys go in the API key field." Apply a similar check to Voice ID, rejecting values that start with "sk_" or are longer than about 32 characters.

### A15. [medium] point(at:) clamps the 300x260 window instead of the 120x90 sprite, so Pip points at the wrong spot near screen edges
